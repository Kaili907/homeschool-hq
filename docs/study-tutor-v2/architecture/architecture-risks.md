# Architecture risks

Risk ratings describe the current seam before Tutor V2 implementation. “Wave 1 control” is the contract/test response; production wiring remains later work.

| ID | Risk | Evidence | Wave 1 control / later action | Rating |
|---|---|---|---|---|
| R-01 | Historical authority conflict: frozen Tutor Core and Bridge 1.0.1 treat assessment/mastery/advance as Tutor-owned, while V2 requires Study authority. A careless adapter could preserve two learning authorities. | `core/engine/adaptive-tutor-engine.ts`; `bridges/tutor-core/adapter-manifest.json`; bridge mappings including `masteryRemainsTutorOwned`; reconciliation manifest | New V2 action API contains no official score/mastery/advance action. W1-08 is additive and maps only proposals into Study. Preserve v0.2/v1 history unchanged. | High |
| R-02 | Answer authority can leak through local Tutor paths. Browser/demo requests carry `correctAnswer` or `expectedAnswer`, and frozen Tutor programs contain accepted answers. | Family Pilot `tutorBridge.ts`; portable runtime `tutor-bridge.ts`; integration-lab accepted bridge; `core/contracts/assessment.ts` | Production import exclusion; V2 provider/context contamination tests; server assessment remains exclusive; no answer-bearing V2 contract. | Critical |
| R-03 | Raw responses/transcripts can become memory, checkpoint, prompt, log, fingerprint, or durable evidence. | frozen engine snapshot/transcript; Family Pilot browser stores; integration-lab local stores; bridge privacy rules explicitly prohibit these fields | Ephemeral bounded memory; exact evidence allowlist; no raw text in durable contracts; lifecycle clearing; privacy/adversarial tests. Later end-to-end log/telemetry audit. | Critical |
| R-04 | Current generic Tutor gateway accepts a provider-specific, open-ended text interaction. ## Residual-risk posture

Wave 1 can proceed with these risks only because it is contract/internal-adapter work with no production web wiring. R-02, R-03, R-05, R-11, and R-16 are release-blocking for any later production enablement until their end-to-end security tests pass. R-09 and R-14 require explicitly owned later convergence rather than Tutor-side workarounds.
