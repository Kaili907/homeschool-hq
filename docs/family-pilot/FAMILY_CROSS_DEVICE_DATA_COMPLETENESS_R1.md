# Family cross-device data completeness R1

## Result

The canonical `hosted-study-sync-state.r2.v1` authority checkpoint now contains the selected learner's useful school state, School Plan and deterministic Auto Planner provenance, and the minimum learner-authored instructional input needed to reconstruct the current screen. The checkpoint remains one server-bound student document with whole-document CAS, idempotency receipts, and explicit revision conflict. Hosted Sync remains default-off; this change does not contact or apply anything to hosted Supabase.

## Durable record inventory

`SYNC_REQUIRED` means Device B must hydrate the record or an exact lossless projection before continuing. `DEVICE_LOCAL` means the record may remain on one device without changing school truth. `DERIVED` means it is recomputed only from synchronized authority. `FORBIDDEN` means it must never enter Hosted Sync.

## Minimum learner-input checkpoint and privacy rationale

The next screen needs to know which attempt, section, item and segment the learner was on; the learner's saved selection or text; whether assessment is pending or already accepted; and the minimized trusted receipt when one exists. Those are the only newly syncable learner-authored fields. They are emitted only for unfinished lesson/assessment assignments; certified work retains its completion/receipt facts without carrying old learner prose. Published curriculum supplies the prompt, choice labels, examples and directions, so none are duplicated. The payload does not contain answer material, scoring logic, Tutor state, audio, labels or inference.

The legacy marker `rawLearnerResponseIncluded` remains false because the unbounded browser record/document is not copied. `instructionalInputIncluded` truthfully marks whether the bounded projection is present. Text is non-empty and capped at 16,000 characters per item; the full authority checkpoint remains capped at 2 MiB and 10,000 input records. Choice input contains only the selected opaque choice reference. Assessment receipts contain only receipt/assessor references, decision and accepted time.

## Reconciliation and conflicts

Every mutation carries the remote base revision, next server revision and one idempotency UUID. The server locks the authority row and either stores exactly the next document, replays the identical receipt, or returns `revision-conflict` with the current server revision. It never chooses a wall-clock winner.

On conflict, the caller keeps the unsent local checkpoint and hydrates the remote checkpoint separately. Auto Planner materializations are append-preserved. Existing learner input records cannot disappear during an accepted transition; an edit to the same attempt/item is accepted only from the current CAS base. The UI can therefore present both versions for recovery when an automatic lossless merge is unsafe.

Offline writes remain local. `OFFLINE` does not mutate the remote revision or clear the local document. Reconnect retries the same idempotency operation against its original base. A committed-but-response-lost retry returns the original receipt; a genuinely stale base returns an explicit recoverable conflict.

## Exact resume proof

The emulator round trip asserts Device A's assignment, lesson, block/session identity, checkpoint revision, segment/page, completed segments, elapsed segment time, School Plan/materialization and saved instructional input. Empty Device B hydrates and re-exports the same canonical checkpoint. Device B then advances progress under CAS and Device A hydrates those later facts. The same suite covers manual work, assessment/receipt, guardian state, safety, planner de-duplication and sibling-preserving selected-student import.

## Backup independence

Hosted Sync is operational continuity; Parent Download Backup is emergency recovery. Backup export/restore retains its separate schema and explicit user action. Neither hydrate nor conflict handling deletes a backup or treats cloud availability as proof that a backup is obsolete.
