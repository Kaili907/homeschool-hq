## Content boundary

- `curriculum-content/manuel-academy/1.0.0/` — the **immutable source release**,
  checked in verbatim (181 files + `SHA256SUMS.txt`, all checksums verified).
  Never edit these files; a new release version gets a new directory.
- `scripts/build-curriculum.mjs` — projects the source into
  `public/curriculum/1.0.0/` (gitignored, regenerated by `npm run dev`/`build`
  or `npm run curriculum:build`). Re-verifies counts, ID uniqueness, and
  schedule coverage on every run and fails the build on drift.
- Chunk layout: `release.json` (tiny), per-grade `catalog.json` + `schedule.json`,
  and per-unit `courses/<course_id>/unit-NN.json`. The app fetches chunks lazily
  (`src/academy/contentClient.ts`); the initial application load fetches **zero**
  curriculum content.

## Student/adult separation

Browser chunks omit `answer_or_scoring_guidance`, `adaptive_tutor_routes`, and
assessment `mastery_interpretation`. Because this host is a static SPA with no
per-request authorization, those fields remain only in the immutable repository
source: the generator emits no protected chunks and the browser has no protected
content loader. The Parent Hub retains progress, mastery evidence, assessment
entry, and pacing controls without publishing guidance. Serving protected
guidance later requires a separately reviewed authenticated surface.

## Identity, state, persistence

- The canonical `Grade` union (src/types.ts) and sync validator grades now
  include `'5' | '7' | '8'` — one authority, extended, not duplicated.
- Student state lives in `Profile.academy` (`AcademyState`, additive/optional,
  schema v2 unchanged): enrollment pinned to a release version, per-lesson
  status + exact-resume segment pointer + append-only mastery occasions,
  per-assessment attempt lists. Validated for sync in `src/sync/provenance.ts`.
- **No database migration is required or included**: the existing
  localStorage + CAS-synced AppState represents everything above.
- Mastery is derived (`academyState.masteryOf`), enforcing the release rule:
  ≥2 met occasions on ≥2 distinct dates with ≥1 independent — a single answer
  can never establish mastery, and guided/independent evidence stay distinct.
- Pacing overrides ride the existing `Profile.pacing` pointers keyed by academy
  course id (nudged from the hub's Academy tab) — expectations only, the source
  curriculum is never rewritten.

## Feature flags (all default OFF)

`VITE_ACADEMY_GRADE_5_ENABLED` / `VITE_ACADEMY_GRADE_7_ENABLED` /
`VITE_ACADEMY_GRADE_8_ENABLED` — independent, exact-string `'true'` only
(`src/academy/featureFlag.ts`). With a flag off, its grade's profiles keep the
pre-existing behavior everywhere.

## Routes

`/academy[/schedule|/course/<id>[/unit/<n>[/assessment|/lesson/<id>]]]`
(`src/academy/academyRoute.ts`). Deep links and refreshes are evaluated at boot
ahead of the picker default (MOUNT-2 pattern) and only for an active profile
whose grade flag is enabled; exits and sign-out normalize the URL back to `/`
(A4-X pattern).

## Adapters (versioned contracts, not yet mounted)

- `src/academy/adapters/tutorContextAdapter.ts` (v1): accepts an explicitly
  supplied protected input from a future authenticated surface and maps it to
  Tutor context; pins `revealsAnswers: false` and
  `gradedWorkPolicy: 'never-complete-graded-work'`. Mounting waits on the
  parked tutor host line (PARKED.md §D).
- `src/academy/adapters/studyContextAdapter.ts` (v1): schedule day →
  study-vocabulary `lessonRef`/`skillRefs`. Mounting waits on the parked Study
