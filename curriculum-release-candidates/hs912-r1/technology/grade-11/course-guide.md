# Grade 11 Technology and Computer Science — Course Guide

**Course ID:** `ma-g11-technology`  
**Version:** 1.0.0  
**Instructional sessions:** 36  
**Typical session:** 45–75 minutes (60–90 in capstone units)  
**Cadence:** weekly

## Course description

A Grade 11 computer-science course focused on professional engineering practice, modular and object-oriented design, web system architecture, applied data science, and evaluated AI literacy.

## Course outcomes

By the end of the course, learners will:

1. Demonstrate the listed Michigan-aligned knowledge and practices through independent, accessible evidence.
2. Explain reasoning, cite evidence, document process, or justify design choices rather than supply unsupported answers.
3. Transfer learning to an unfamiliar task, text, situation, dataset, performance, or project.
4. Use feedback and error evidence to revise without shame or character judgments.
5. Complete the course capstone: **A documented Grade 11 engineering project with an architecture decision record, version history, automated test coverage, accessibility conformance evidence, and a security and privacy review.**

## Instructional model

Six-session units run: Launch and diagnostic; Explicit model; Guided practice; Application or project; Mastery check; Correction and reflection. Twelve-session units run: Launch and diagnostic; Concept model A; Guided practice A; Independent application A; Concept model B; Guided practice B; Investigation or close reading; Reteach and varied practice; Performance task build; Synthesis and review; Unit assessment; Correction and reflection.

Every topic in a unit receives at least one instructional lesson before any
assessment or correction lesson. Mastery-check, assessment, synthesis, and
correction lessons are scoped to the whole unit rather than to a single topic.
Lessons are resumable by segment, media is optional, and a readable fallback is
always specified.

## Mastery and grading

- One correct answer never establishes mastery.
- Unit assessments combine concept, representation or source use, application, error or claim analysis, connection, performance evidence, and reflection. Capstone units add a defense-and-response-to-critique prompt.
- Suggested reporting: **Secure**, **Developing**, or **Not Yet**, supported by evidence rather than a single percentage.
- Reassessment uses fresh items or a new application after targeted instruction.
- Approved breaks, accommodations, voice/no-voice choices, and alternate response modes are not failures.
- Parent summaries show target, completion, evidence type, and next step; they exclude raw private reflections, diagnosis language, and unnecessary personal data.

## Scope and sequence

| Unit | Title | Days | Standards anchors | Performance task |
| --- | --- | --- | --- | --- |
| 1 | Software Engineering Practice and Collaborative Version Control | 6 | Michigan Computer Science: Algorithms and Programming | Run a full engineering workflow on a small feature with tracked issues, branches, a resolved merge conflict, review notes, and test evidence. |
| 2 | Object-Oriented and Modular Design | 6 | Michigan Computer Science: Algorithms and Programming | Refactor a procedural program into a modular design and demonstrate preserved behavior with tests. |
| 3 | Web and Application Architecture | 6 | Michigan Computer Science: Algorithms and Programming; Networks and the Internet | Build a multi-view accessible web application against a mock interface with documented architecture decisions. |
| 4 | Applied Data Science and Modeling | 6 | Michigan Computer Science: Data and Analysis | Produce a reproducible data analysis with provenance, uncertainty, stated limitations, and an honest visualization set. |
| 5 | AI, Machine Learning Literacy, and Evaluation | 6 | Michigan Computer Science: Data and Analysis; Impacts of Computing | Evaluate a supplied model or AI output against metrics, baselines, bias analysis, and disclosure requirements. |
| 6 | Engineering Project with Test and Accessibility Evidence | 6 | Michigan Computer Science: Algorithms and Programming; Impacts of Computing | Deliver an engineered application with an architecture record, test coverage, accessibility conformance, and a maintenance plan. |

## Capstone

A documented Grade 11 engineering project with an architecture decision record, version history, automated test coverage, accessibility conformance evidence, and a security and privacy review.

The capstone may be presented publicly, privately, in writing, orally, through a demonstration, or in another accessible format that preserves the learning targets.
