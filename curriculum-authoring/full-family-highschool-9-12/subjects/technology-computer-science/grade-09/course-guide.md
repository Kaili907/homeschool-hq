# Grade 9 Technology and Computer Science — Course Guide

**Course ID:** `ma-g9-technology`  
**Version:** 1.0.0  
**Instructional sessions:** 36  
**Typical session:** 45–75 minutes (60–90 in capstone units)  
**Cadence:** weekly

## Course description

A Grade 9 computer-science course that takes the Grade 8 exit point into formal algorithm design, disciplined programming with compound logic and modular structure, systematic testing under version control, systems literacy, and technically demanding accessible design.

## Course outcomes

By the end of the course, learners will:

1. Demonstrate the listed Michigan-aligned knowledge and practices through independent, accessible evidence.
2. Explain reasoning, cite evidence, document process, or justify design choices rather than supply unsupported answers.
3. Transfer learning to an unfamiliar task, text, situation, dataset, performance, or project.
4. Use feedback and error evidence to revise without shame or character judgments.
5. Complete the course capstone: **A documented Grade 9 foundations software project with algorithm design, version history, test evidence, an accessibility audit, and a privacy and security review.**

## Instructional model

Six-session units run: Launch and diagnostic; Explicit model; Guided practice; Application or project; Mastery check; Correction and reflection. Twelve-session units run: Launch and diagnostic; Concept model A; Guided practice A; Independent application A; Concept model B; Guided practice B; Investigation or close reading; Reteach and varied practice; Performance task build; Synthesis and review; Unit assessment; Correction and reflection.

Every topic in a unit receives at least one instructional lesson before any
assessment or correction lesson. Mastery-check, assessment, synthesis, and
correction lessons are scoped to the whole unit rather than to a single topic.
Lessons are resumable by segment, media is optional, and a readable fallback is
always specified.

## Mastery and grading

- One correct answer never establishes mastery.
- Unit assessments combine concept, representation or source use, application, error or claim analysis, connection, performance evidence, and reflection. Capstone units add a defense-and-response-to-critique prompt.
- Suggested reporting: **Secure**, **Developing**, or **Not Yet**, supported by evidence rather than a single percentage.
- Reassessment uses fresh items or a new application after targeted instruction.
- Approved breaks, accommodations, voice/no-voice choices, and alternate response modes are not failures.
- Parent summaries show target, completion, evidence type, and next step; they exclude raw private reflections, diagnosis language, and unnecessary personal data.

## Scope and sequence

| Unit | Title | Days | Standards anchors | Performance task |
| --- | --- | --- | --- | --- |
| 1 | Computational Thinking and Problem Decomposition | 6 | Michigan Computer Science: Algorithms and Programming | Design and hand-trace an algorithm for a defined user need, documenting decomposition and abstraction choices. |
| 2 | Programming Foundations: Data, Control, and Functions | 6 | Michigan Computer Science: Algorithms and Programming | Build a modular program that uses compound conditions, nested iteration, and composed functions to solve a stated problem for a real user. |
| 3 | Debugging, Testing, and Version Control | 6 | Michigan Computer Science: Algorithms and Programming | Repair a supplied defective program and deliver a commit history, a defect log, a failing test that reproduces the bug, and a verified fix. |
| 4 | Computing Systems, Hardware, and Abstraction | 6 | Michigan Computer Science: Computing Systems | Diagram a computing system across its abstraction layers and document a reproducible troubleshooting protocol. |
| 5 | Human-Centered and Accessible Interface Design | 6 | Michigan Computer Science: Impacts of Computing; Algorithms and Programming | Build a responsive, accessible multi-view interface with validated forms, then document an accessibility audit and a user-test revision log. |
| 6 | Foundations Project and Impact Review | 6 | Michigan Computer Science: Algorithms and Programming; Impacts of Computing | Deliver a foundations software project with version history, test evidence, an accessibility audit, and a privacy and security review. |

## Capstone

A documented Grade 9 foundations software project with algorithm design, version history, test evidence, an accessibility audit, and a privacy and security review.

The capstone may be presented publicly, privately, in writing, orally, through a demonstration, or in another accessible format that preserves the learning targets.
